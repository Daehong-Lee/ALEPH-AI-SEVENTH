# 플랜두씨 다이어리 2

Diary 1과 별도의 Supabase 프로젝트에서 사용하는 개인 인증형 다이어리입니다.

## 핵심 흐름

1. 첫 화면은 로그인/회원가입입니다.
2. 로그인 후에만 내 자료가 열립니다.
3. 계획을 만들 때 계획의 하위 항목인 할 일을 함께 입력합니다.
4. 별도의 `할 일` 탭은 없습니다.
5. 계획 화면에서 각 항목의 `완료`를 누르면 항목이 진행 중 목록에서 완료 목록으로 이동합니다.
6. 완료 버튼은 `d2_complete_task_once()` RPC를 통해 완료 기록과 실행 기록을 자동 생성합니다.
7. 실행 기록은 사용자가 직접 시간을 입력하지 않으며 `Asia/Seoul`의 완료 날짜별로 묶어 보여줍니다.
10. `완료` 탭은 계획 탭과 분리되어 있으며 완료 시각 순으로만 표시합니다. 완료된 항목은 수정할 수 없습니다.
11. 할 일 태그는 계획, 완료, 실행 기록 화면에서 표시합니다.
12. 모든 공개 테이블은 `d2_` 접두사를 사용하여 Diary 1과 이름을 분리합니다.

## Supabase 설정

1. Diary 2 전용 Supabase 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase.sql` 전체를 최초 1회 실행합니다.
3. Authentication에서 Email/Password 가입 정책을 확인합니다.
4. `app.js`의 `SUPABASE_URL`과 anon/publishable key를 입력합니다.
5. `service_role` 또는 secret key는 브라우저 코드에 넣지 않습니다.

## 인증/권한

- 사용자 식별은 Supabase Auth를 사용합니다.
- 공개 데이터 테이블의 소유자는 `user_id`입니다.
- RLS가 `auth.uid() = user_id`를 기준으로 읽기/쓰기/삭제를 제한합니다.
- 돌아보기에서 넘길 대상 계획도 현재 사용자 소유의 기존 계획인지 DB 정책으로 확인합니다.
- 로그아웃 후에는 인증된 자료 화면을 열지 않습니다.

## 실행 기록

실행 기록은 별도 입력 폼이 없습니다. 계획의 하위 항목을 완료할 때 현재 시각을 기준으로 자동 생성됩니다. 완료 날짜는 `Asia/Seoul`로 계산되어 일자별로 분류됩니다.

현재 실행 기록에는 별도의 실제 소요시간 입력을 두지 않습니다. 따라서 화면은 실제 소요시간을 측정했다고 주장하지 않고, 완료된 항목과 그 항목에 입력된 예상시간을 구분합니다.

## 아직 구현하지 않은 것

- 로그인 시도 횟수 제한/브루트포스 방어는 별도로 구현하지 않았습니다.
- 비밀번호 재설정 UI도 기본 범위에는 포함하지 않았습니다.
